# Focus Flight UI 设计系统指南

## 核心产品定位与理念（核心产品定位与隐喻）
- **软件本质**: Focus Flight 是一款**可爱、解压、游戏化**的个人专注与番茄钟应用。
- **飞行包装**: “飞行”是外层包装：航线、起飞、巡航、停机坪等。
- **最高准则**: UI 风格必须是温馨、可爱、轻量化的，摒弃沉重严肃的赛博朋克或战术风，拥抱更贴近大自然、云端、猫咪等解压元素的视觉体验。

---

## 视觉基因与设计标记（设计基因）

1. **色彩系统（色彩系统）**:
   - **主背景色（暖色背景）**: `#FAF7F2` 或 `#FDFBF7` (暖白/米白色，带来温馨解压感)
   - **强调色/主按钮色（珊瑚红强调色）**: `#F06553` 或 `#FF6B6B` (珊瑚红，用于按钮、选中状态边框、打勾图标等)
   - **次强调色（天空蓝次强调色）**: `#60A5FA` 或主题内的天空蓝色
   - **主文字色（主文字色）**: `#1E293B` 或 `#334155` (深灰/藏青色)
   - **次级/提示文字（次级提示文字色）**: `#94A3B8` 
   - **卡片背景（卡片背景色）**: `#FFFFFF`

2. **圆角与阴影（圆角与阴影）**:
   - 底部弹窗大圆角: `borderRadius({ topLeft: 32, topRight: 32 })`
   - 主操作按钮（胶囊型）: `borderRadius(32)`
   - 主题封面卡片: `borderRadius(16)`
   - 阴影（柔和浅阴影）: `shadow({ radius: 12, color: 'rgba(0, 0, 0, 0.08)', offsetY: 4 })` 柔和的浅色阴影。

## 核心 ArkTS 组件开发规范

### 1. 底部弹窗（底部弹窗抽屉）标准写法
- 背景必须使用暖色 `#FAF7F2`。
- 顶部必须有灰色拖拽指示条（拖拽指示条），如 `#E2E8F0`。
- 标题区域应使用深色主文本，字体较大（如 18vp），字重 Medium 或 Bold。
- 右上角关闭按钮应为圆形浅灰色背景（如 `#F1F5F9`），内含深灰色 `✕` 图标。
- 底部应提供宽大圆润的红色强调操作按钮（如“应用主题”）。

### 2. 列表与网格卡片（主题与皮肤卡片）
- 未选中时无边框。
- 选中时：增加珊瑚红边框 `border({ width: 2, color: '#F06553' })`，并在右下角叠加带有 `✓` 的珊瑚红圆形徽章。
- 不可用/未解锁时：在右下角叠加灰色锁图标徽章。

### 3. 公共组件与原生组件使用规范
- 遇到底部抽屉/面板弹窗需求，**优先使用 HarmonyOS ArkUI 原生 `@CustomDialog` + `CustomDialogController({ alignment: DialogAlignment.Bottom, customStyle: true })` 机制**。
- 严禁自行使用绝对定位手写伪弹窗。
- **严格遵循最小改动原则**: 修改代码时仅更改与当前需求直接相关的最小必要行，保留用户自定义的坐标或配置。

---

### 4. 资源规划与代码拆分规范（资源架构与代码模块化）
- **静态资源**: `rawfile` 内分类建立子目录 `css/`, `js/`, `models/`, `textures/`, `data/`。
- 保持代码干净精简，避免臃肿单体文件。

---

### 5. 地图战术航线大圆弧生成规范
- (保留原有航线算法约束) 严禁尖锐折角，采用高密度二次贝塞尔切线倒角算法保证航线圆润。

---

### 6. 专注模式与游戏化规范 (详见 focus-flight-modes-and-gameplay)
- **标准飞行模式（轻度）**: 允许后台挂机与随时查阅，专注与里程平滑累积。
- **深度巡航模式（严格）**: 开启“离开即迫降”检测，切出应用超过 10 秒即判定专注失败。
